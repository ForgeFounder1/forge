# Forge platform data format (schemaVersion 1)

One file per platform in `data/platforms/<id>.js`. No JSON fetch (the app must open from `file://`), so each file is a script:

```js
window.FORGE_PLATFORMS = window.FORGE_PLATFORMS || {};
window.FORGE_PLATFORMS["<id>"] = { /* platform object */ };
```

Each platform gets its own build sheet in localStorage (`forge.builds.v2`). Then add one line to `index.html` in the PLATFORM DATA FILES block: `<script src="data/platforms/<id>.js"></script>`.
Use the same `<id>` as the "coming soon" entry in `CATALOG` in `app.js` (e.g. `f150-2004-2008`, `ram1500-2009-2018`, `gmt900-2007-2014`, `tacoma-2005-2023`, `wrangler-jk-jl`, `mustang-s197-s550`, `camaro-2010-2015`, `civic-2006-2021`, `wrx-2015-2021`, `mustang-s197-s550`, `camaro-5th`, `civic`, `wrx`, `miata`) so the loaded file replaces the placeholder. GMT800 is generated by `scripts/build_app_gmt800.js`; copy that pattern.

## Rules for data
- Copy numbers exactly as the source shows them. Never round, convert or average. Keep conflicts as separate items with `disputed: true`.
- Every fact carries `conf` and `src` (when a source exists).
- Visible text must not contain em-dashes. Use "n/a" for empty cells.
- Dates: `YYYY-MM-DD`. Prices: numbers in USD (`77.0`), or `null` when not stated.

## Shared shapes
| Name | Shape |
|---|---|
| `Source` | `{ "label": string, "url": string }` |
| `Conf` | one of `"verified"`, `"verified-secondary"`, `"forum"`, `"video"`, `"unconfirmed"`, `"unknown"`, or an array of these for mixed items. Badges: Verified (secondary shows as Verified, with a tooltip saying it came from a secondary page), Forum-reported, Video-reported, Unconfirmed, Unknown. |
| `Fact` | `{ "label": string, "text": string, "conf": Conf, "disputed"?: bool, "src": Source[] }` |
| `Table` | `{ "columns": string[], "rows": string[][], "conf"?: Conf, "src"?: Source[], "note"?: string, "disputedRows"?: int[] (row indexes), "rowSrc"?: string[] (url per row) }`. A column whose header contains "Confidence" may hold a Conf key (or array of keys) and renders as badges. |
| `Tip` | `{ "text": string, "source_url": string, "source_name": string, "confidence": "forum" \| "video" \| "verified", "date_checked": "YYYY-MM-DD", "disputed"?: bool }`. One source per tip, a page that was actually opened. Rules in `../TIPS-SPEC.md`. |
| `Step` | `{ "text": string, "conf"?: Conf (only when different from the guide), "disputed"?: bool }` |

### Stance
`{ "id", "title", "subtitle", "conf", "disputed"?, "src": Source[], "note": string, "noteSrc"?: Source[], "rows": Row[], "colDrop"?: string, "colVehicle"?: string }`
`colDrop` / `colVehicle` rename the "Drop" / "Truck" column headers (e.g. "Gen" / "Setup" on car platforms).
Row: `{ "wheel": string, "tire": string, "fit": string, "conf": Conf, "disputed"?: bool, "src"?: Source[], "drop"?: string, "truck"?: string }`. Include `drop` and `truck` on lowered rows (the table adds those columns when the first row has `drop`). Rows without `src` use the stance `src`.

### Problem
`{ "id", "title", "years": string, "symptoms": string, "cause": string, "fix": string, "parts": partId[], "guide"?: guideId, "conf": Conf, "confNote"?: string, "disputed"?: bool, "src": Source[], "tips"?: Tip[] }`
`tips` (optional) shows as an "Owner tips" block on the problem page.

### Guide
`{ "id", "type": "diy" | "swap", "title", "summary", "conf", "disputed"?, "src": Source[], "steps": Step[], "torque": Table | null, "parts": partId[], "tips"?: Tip[] }`
`tips` (optional) shows as an "Owner tips" block on the guide page.
Torque tables use columns `["Fastener", "Spec"]` (or `["Fastener", "<variant A>", "<variant B>"]` when specs differ by model, e.g. 1500 vs 2500) with the spec text copied verbatim (e.g. `"190 N·m (140 lb-ft)"`).

### Part (same as `gmt800-deals.json` items)
```json
{
  "id": "suspension-belltech-6400",
  "platform": "GMT800",
  "category": "Suspension & Stance",
  "name": "Rear 2\" drop shackle kit (level stance)",
  "brand": "Belltech",
  "part_number": "6400",
  "fitment": { "years": "...", "models": ["..."], "drive": ["2WD","4WD"], "cab": "...", "bed": "...", "engines": ["..."], "position": "...", "trans": "...", "steering": "...", "min_wheel": "...", "notes": "...", "hunter_fit": true, "hunter_note": "..." },
  "offers": [
    { "seller": "Belltech (manufacturer)", "price": 77.0, "price_unit": "listing|each", "shipping_note": "...", "url": "https://...", "checked": "2026-10-10", "status": "verified|unverified", "source_note": "..." }
  ],
  "notes": "...",
  "best_offer": { "seller": "...", "price": 77.0, "url": "https://...", "status": "verified" },
  "source": "master-guide",
  "tips": [ { "text": "...", "source_url": "https://...", "source_name": "Forum: thread title", "confidence": "forum", "date_checked": "2026-10-11" } ]
}
```
- `bed` (optional) is the bed length the listing names, e.g. "Short bed (std cab, 119 in WB)". The app reads short/long from words like short, SB, 6.5, 5.8, 119, 143.5 / long, LB, 8 ft, 133, 157.5.
- `fit_src` (optional, set by the build from `scripts/<platform>/h_fitment.js`): `[{ "fields": ["years", ...], "label", "url" }]`, the page that confirmed fields that were filled in. Fills never overwrite existing fields.
- "Fits my vehicle": a saved selector vehicle (year, model, cab, bed, drive, engine) is compared with `years`, `drive`, `cab`, `bed`, `models` and `engines`. A field that rules the part out gives "Doesn't fit"; a missing year, or a missing drive/cab/bed in a category where other parts list it, gives "Check fitment".
- All `fitment` keys are optional. `hunter_fit` may be `true`, `false`, or a short string like `"Only if 4WD"`.
- `best_offer` is the lowest **verified** listed price, or `null` when there is none. The app highlights the offer whose seller, url and price match it. When it is `null`, the build sheet uses the lowest priced offer and marks it Unverified.
- `tips` is optional (`Tip[]`) and renders as "Owner tips" on the part detail page. Parts without it are unchanged.
- `price_unit: "each"` means per item (the build sheet has a quantity control).

## Source classification (apply the same way on every platform)
- **Verified**: factory documents (owner's manuals, brochures, spec sheets, TSBs, recalls) and manufacturer, retailer or wheel-maker fitment guides and product pages that were opened (e.g. Apex, Mr. Wheel Deal, JM Automotive, Beefcake, RallySport Direct).
- **Verified (secondary)**: service-manual mirrors and reference sites (diagnostdata, tighttorque, honcivic, wheel-size, wheeloffset).
- **Forum-reported**: forums, owner threads, Reddit and blogs (e.g. ThreePiece.us), including a blog quoting owners.
- **Video-reported**: YouTube, cited by title/channel only.
- **Unconfirmed**: search snippets or syntheses, blocked pages.
- A row backed by both a Verified and a Forum source carries both badges.

## Repair catalog parts (`catalog`, added 2026-10-20)
Large RockAuto catalogs are kept out of the main platform file so phones only download what they open.
- Pipeline: `node scripts/build_app_<platform>.js` (main file), then `python3 scripts/expand/integrate.py [slug]`. The second step reads `data/expanded/<slug>-parts.json` and `scripts/gapfill/<slug>.json`, and is safe to re-run.
- Hand-built parts stay in `parts` and gain `subcategory` (part type) and `tier` when the expanded file has them.
- Catalog parts (`source: "rockauto-catalog"`) go to `app/data/parts/<slug>/<n>.js`, one file per category: `(window.FORGE_PARTS = ...)["<slug>/<n>"] = Part[]`. The app injects the script when a category, "All parts", a missing part id, or the platform search needs it, then appends the parts to `parts`.
- Dedupe: brand + part number (non-alphanumerics dropped). A catalog pick that matches a hand-built part is skipped, so the hand-built part keeps its tips, notes and fitment.
- Categories: catalog parts use the repair systems Engine, Ignition, Fuel System, Cooling, HVAC, Electrical, Brakes, Steering, Suspension, Drivetrain, Exhaust & Emissions, Body, Lighting, Interior, Filters & Fluids. If the platform already has a category for the same system (first word matches, e.g. "Suspension & Stance", "Exhaust & Headers"), that name is used.
- Extra Part fields: `subcategory` (RockAuto part type, e.g. "Blower Motor"), `tier` (`economy` = cheapest listing, `oe` = cheapest OE brand, `premium` = cheapest premium brand, `premium-upper` = priciest premium brand when 40%+ above the cheapest premium), `fitment.checked_only: true`.
- `fitment.checked_only`: `years`, `engines` and `models` list the representative vehicles that were crawled, not the full range. Outside them the app shows "Check fitment" (never "Doesn't fit").
- Compaction in the part files (restored by the app on load): offers drop `shipping_note` when it is "Shipping calculated at checkout (not verified)" and `price_unit` when it is "listing"; `best_offer` is dropped when it equals the first lowest-priced verified offer.
- Main file meta: `catalog = { note, vehicles: url[], generated, count, files: [{ file, category, count, types, from, bytes }] }`. Category counts and "from" prices on the Parts screen come from this meta, so no part file loads until a category opens.

## Maintenance and reference (`reference`, optional, any platform)
Shown as the "Maintenance and reference" section when present, and searched by the platform search.
```json
{ "caveat": "year-applicability note for the whole set",
  "sections": [ { "id": "maintenance|quickref|vin|codes|...", "title": "...", "short": "menu subtitle", "intro"?: "...",
    "blocks": [ { "title": "...", "conf": Conf, "src": Source[], "years"?: "Applies to ...", "text"?: "...", "items"?: string[], "table"?: Table, "caveat"?: "..." } ] } ] }
```
- Standard section ids: `maintenance` (schedule, fluids and capacities, filter/plug part numbers), `quickref` (bulbs, fuses, tire pressure, alignment and ride height, paint codes, towing/payload, hitch limits), `vin` (VIN by position, RPO/option codes), `codes` (trouble codes: code, meaning, likely causes, years; `table.rowSrc` links each row's source).
- Every block needs `conf` and at least one `src`. Put year limits in `years` when the data comes from one model year's manual.
- Gap-fill input lives in `scripts/gapfill/<slug>.py` (hand-entered from `/workspace/forge-research/gapfill/*.md`), which writes `<slug>.json` with `reference`, `guides` (new DIY guides with factory torque, ids start `gf-`), `conflicts` (appended by topic), `resolved` (what the research settled) and `unknowns` (replaces the platform list).
- Search index: `data/parts/<slug>/index.js` sets `window.FORGE_PIDX[slug] = [[id, name, brand, part_number, part type, category, lowest verified price], ...]` (meta `catalog.index`). My Garage search loads every platform's index the first time it is used and lists catalog parts that are not loaded yet; opening a hit loads that platform's part files.
