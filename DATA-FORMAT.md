# Forge platform data format (schemaVersion 1)

One file per platform in `data/platforms/<id>.js`. No JSON fetch (the app must open from `file://`), so each file is a script:

```js
window.FORGE_PLATFORMS = window.FORGE_PLATFORMS || {};
window.FORGE_PLATFORMS["<id>"] = { /* platform object */ };
```

Each platform gets its own build sheet in localStorage (`forge.builds.v2`). Then add one line to `index.html` in the PLATFORM DATA FILES block: `<script src="data/platforms/<id>.js"></script>`.
Use the same `<id>` as the "coming soon" entry in `CATALOG` in `app.js` (e.g. `f150-2004-2008`, `ram1500-2009-2018`, `gmt900-2007-2014`, `tacoma-2005-2023`, `wrangler-jk-jl`, `mustang-s197-s550`, `camaro-2010-2015`, `civic-2006-2021`, `wrx-2015-2021`, `mustang-s197-s550`, `camaro-5th`, `civic`, `wrx`, `miata`) so the loaded file replaces the placeholder. GMT800 is generated by `scripts/build_app_gmt800.js`; copy that pattern.

## Rules for data
- Copy numbers exactly as the source shows them. Never round, convert or average. Keep conflicts as separate items with `disputed: true`.
- Every fact carries `conf` and `src` (when a source exists).
- Visible text must not contain em-dashes. Use "n/a" for empty cells.
- Dates: `YYYY-MM-DD`. Prices: numbers in USD (`77.0`), or `null` when not stated.

## Shared shapes
| Name | Shape |
|---|---|
| `Source` | `{ "label": string, "url": string }` |
| `Conf` | one of `"verified"`, `"verified-secondary"`, `"forum"`, `"video"`, `"unconfirmed"`, `"unknown"`, or an array of these for mixed items. Badges: Verified (secondary shows as Verified, with a tooltip saying it came from a secondary page), Forum-reported, Video-reported, Unconfirmed, Unknown. |
| `Fact` | `{ "label": string, "text": string, "conf": Conf, "disputed"?: bool, "src": Source[] }` |
| `Table` | `{ "columns": string[], "rows": string[][], "conf"?: Conf, "src"?: Source[], "note"?: string, "disputedRows"?: int[] (row indexes), "rowSrc"?: string[] (url per row) }`. A column whose header contains "Confidence" may hold a Conf key (or array of keys) and renders as badges. |
| `Step` | `{ "text": string, "conf"?: Conf (only when different from the guide), "disputed"?: bool }` |

### Stance
`{ "id", "title", "subtitle", "conf", "disputed"?, "src": Source[], "note": string, "noteSrc"?: Source[], "rows": Row[], "colDrop"?: string, "colVehicle"?: string }`
`colDrop` / `colVehicle` rename the "Drop" / "Truck" column headers (e.g. "Gen" / "Setup" on car platforms).
Row: `{ "wheel": string, "tire": string, "fit": string, "conf": Conf, "disputed"?: bool, "src"?: Source[], "drop"?: string, "truck"?: string }`. Include `drop` and `truck` on lowered rows (the table adds those columns when the first row has `drop`). Rows without `src` use the stance `src`.

### Problem
`{ "id", "title", "years": string, "symptoms": string, "cause": string, "fix": string, "parts": partId[], "guide"?: guideId, "conf": Conf, "confNote"?: string, "disputed"?: bool, "src": Source[] }`

### Guide
`{ "id", "type": "diy" | "swap", "title", "summary", "conf", "disputed"?, "src": Source[], "steps": Step[], "torque": Table | null, "parts": partId[] }`
Torque tables use columns `["Fastener", "Spec"]` (or `["Fastener", "<variant A>", "<variant B>"]` when specs differ by model, e.g. 1500 vs 2500) with the spec text copied verbatim (e.g. `"190 N·m (140 lb-ft)"`).

### Part (same as `gmt800-deals.json` items)
```json
{
  "id": "suspension-belltech-6400",
  "platform": "GMT800",
  "category": "Suspension & Stance",
  "name": "Rear 2\" drop shackle kit (level stance)",
  "brand": "Belltech",
  "part_number": "6400",
  "fitment": { "years": "...", "models": ["..."], "drive": ["2WD","4WD"], "cab": "...", "engines": ["..."], "position": "...", "trans": "...", "steering": "...", "min_wheel": "...", "notes": "...", "hunter_fit": true, "hunter_note": "..." },
  "offers": [
    { "seller": "Belltech (manufacturer)", "price": 77.0, "price_unit": "listing|each", "shipping_note": "...", "url": "https://...", "checked": "2026-10-10", "status": "verified|unverified", "source_note": "..." }
  ],
  "notes": "...",
  "best_offer": { "seller": "...", "price": 77.0, "url": "https://...", "status": "verified" },
  "source": "master-guide"
}
```
- All `fitment` keys are optional. `hunter_fit` may be `true`, `false`, or a short string like `"Only if 4WD"`.
- `best_offer` is the lowest **verified** listed price, or `null` when there is none. The app highlights the offer whose seller, url and price match it. When it is `null`, the build sheet uses the lowest priced offer and marks it Unverified.
- `price_unit: "each"` means per item (the build sheet has a quantity control).

## Source classification (apply the same way on every platform)
- **Verified**: factory documents (owner's manuals, brochures, spec sheets, TSBs, recalls) and manufacturer, retailer or wheel-maker fitment guides and product pages that were opened (e.g. Apex, Mr. Wheel Deal, JM Automotive, Beefcake, RallySport Direct).
- **Verified (secondary)**: service-manual mirrors and reference sites (diagnostdata, tighttorque, honcivic, wheel-size, wheeloffset).
- **Forum-reported**: forums, owner threads, Reddit and blogs (e.g. ThreePiece.us), including a blog quoting owners.
- **Video-reported**: YouTube, cited by title/channel only.
- **Unconfirmed**: search snippets or syntheses, blocked pages.
- A row backed by both a Verified and a Forum source carries both badges.
